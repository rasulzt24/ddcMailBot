# MailDDC — корпоративная почта в Telegram

Django + aiogram 3. Уведомления о новых письмах (со вложениями, типом, копией и цепочкой),
ответ / ответ всем / пересылка, новые письма с копией и файлами.

## Архитектура

```
┌────────────┐   IMAP 993 / SMTP 587   ┌──────────────────────┐
│ Почтовый   │ ◄────────────────────── │ mail_worker          │  python manage.py mail_worker
│ сервер     │                         │  • опрос INBOX        │
└────────────┘                         │  • отправка очереди   │
                                       └──────────┬───────────┘
                                                  │ PostgreSQL (источник правды)
                                                  │ Redis pub/sub (мгновенные «пинки», опционально)
                                       ┌──────────┴───────────┐
   Пользователи Telegram ◄──────────── │ runbot (aiogram 3)    │  python manage.py runbot
                                       │  • хендлеры, FSM      │
                                       │  • Notifier           │
                                       └──────────────────────┘
                                       Django admin: /admin/
```

Воркер и бот — два отдельных процесса, общаются через БД. Redis лишь ускоряет доставку
событий и хранит FSM-черновики; без него всё работает через опрос БД (раз в 3–15 с).

### Приложения
- `apps/accounts` — `TelegramUser` (статус: ожидает / активен / заблокирован, суперадмин, настройки).
- `apps/mail` — модели и сервисы почты:
  - `MailAccount` — ящик пользователя (пароль зашифрован Fernet), состояние синхронизации;
  - `MailThread` — цепочка переписки (по `In-Reply-To`/`References`, затем по теме);
  - `MailMessage` + `MessageRecipient` + `MailAttachment` — письма (вход/исход), получатели, файлы;
  - `OutgoingMessage` + `OutgoingAttachment` — очередь отправки с повторами;
  - `Contact` — адресная книга (автоматически из писем), поиск получателя по имени;
  - `TelegramNotification` — связь карточки в Telegram с письмом (быстрый ответ реплаем).
  - `services/`: `parser` (MIME), `imap`, `smtp`, `sync`, `storage`, `compose`, `events`.
- `bot/` — aiogram-бот: `handlers/` (start, mailbox, messages, compose, settings, admin), `notifier`, `render`.

## Возможности бота
- 📩 Карточка нового письма: от кого, кому, **копия** («👁 Вы в копии»), тема, дата, важность,
  тип (**🆕 новое / ↩️ ответ / ↪️ переслано / 🤖 автоответ / 📅 приглашение**), список вложений,
  позиция в цепочке. Текст — только новая часть, без цитаты (сворачиваемый блок).
- Вложения приходят файлами сразу (отключаемо); встроенные картинки подписей — по кнопке «🖼».
- «📜 История» — вся цепочка (входящие и ваши ответы), каждое письмо можно открыть.
- «📄 Полностью» — весь текст с историей, HTML-версия, оригинал `.eml`.
- ↩️ Ответить / ↩️ Всем / ↪️ Переслать (с вложениями оригинала, можно выключить).
- ✉️ Новое письмо: Кому → Копия → Тема → Текст → Файлы → предпросмотр с правкой любого поля.
  Получателей можно вводить именем («Иванов») — бот найдёт в адресной книге.
- Быстрый ответ: ответьте (reply) на карточку письма в Telegram — бот соберёт ответ.
- ✅ Прочитано / ✉️ Непрочитано — синхронизируется с сервером.
- 📥 Входящие, 📤 Отправленные, 🔎 Поиск, ⚙️ Настройки (подпись, имя отправителя, уведомления).
- 🛡 Суперадмин: подтверждение/блокировка пользователей, статистика, проблемные ящики, рассылка.

## Запуск

```bash
cd mailbot
python -m venv .venv && .venv\Scripts\activate     # или используйте ../.venv
pip install -r requirements.txt
copy .env.example .env                               # заполнить (см. ниже)
python manage.py migrate
python manage.py createsuperuser                     # для /admin/
python manage.py test apps.mail                      # тесты парсера

# два процесса:
python manage.py mail_worker
python manage.py runbot
# (опционально) админка:
python manage.py runserver
```

Обязательно в `.env`: `TELEGRAM_BOT_TOKEN`, `SUPERADMIN_TELEGRAM_ID`, `DB_*`, `MAIL_ENCRYPTION_KEY`
(не менять после подключения ящиков!). Рекомендуется `REDIS_URL`.

## Прод
**Развёртывание на Linux-сервере в Docker — см. [DEPLOY.md](DEPLOY.md).**

- Запускать `mail_worker` и `runbot` как сервисы (systemd / NSSM на Windows / docker compose),
  с автоперезапуском. Воркер должен быть **один** (или использовать `select_for_update` — уже есть для очереди).
- `DJANGO_DEBUG=False`, `/admin/` — за VPN/HTTPS.
- Папка `media/` — письма и вложения; бэкапить вместе с БД.

## Хранение файлов
Вложения, файлы исходящих писем и (опционально) оригиналы `.eml` хранятся через Django Storage:
- по умолчанию — локальный диск `MEDIA_ROOT` (`mailbot/media/`);
- MinIO / S3 — заполнить `S3_ENDPOINT_URL`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` и перенести
  уже сохранённые файлы: `python manage.py mail_move_storage` (с `--delete` — удалить локальные копии).

В Telegram файл загружается один раз, дальше бот переиспользует `file_id` — повторные отправки мгновенные
и хранилище не читают. `MAIL_STORE_RAW=False` (по умолчанию) — оригинал `.eml` не хранится, а скачивается
с IMAP по кнопке «📦 Оригинал .eml»; это экономит ~половину места.
